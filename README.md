## Аннотация

Программа представляет собой серверную часть веб-сервиса мониторинга информационной безопасности серверных приложений. Backend обеспечивает прием, хранение, обработку и анализ событий безопасности, а также предоставляет REST API для взаимодействия с frontend-приложением.
 
---


# 1\. Общие сведения


## Обозначение и наименование программы

Наименование:<br>«Backend веб-сервиса мониторинга информационной безопасности серверных приложений»

Обозначение:<br>Security Monitoring Backend System
 
---


## Программное обеспечение, необходимое для функционирования программы

Для работы программы требуется:


*   Go 1.24+

*   PostgreSQL 16+

*   Docker / Docker Compose


---


## Языки программирования

Программа разработана с использованием:


*   Go

*   SQL


---


# 2\. Функциональное назначение

Программа предназначена для:


*   приема событий информационной безопасности;

*   хранения событий;

*   выполнения корреляции угроз;

*   формирования инцидентов;

*   предоставления REST API;

*   обработки аналитических запросов.


Функциональные ограничения:


*   система не осуществляет активную блокировку атак;

*   анализ выполняется на основе поступающих событий;

*   производительность зависит от параметров PostgreSQL.


---


# 3\. Описание логической структуры


## Алгоритм работы программы

Backend выполняет:


1.  Прием событий через REST API;

2.  Валидацию данных;

3.  Сохранение событий в PostgreSQL;

4.  Корреляцию событий;

5.  Формирование инцидентов;

6.  Предоставление аналитических данных frontend-приложению.


---


## Используемые методы

Используются:


*   REST API;

*   многослойная архитектура;

*   ULID идентификаторы;

*   JSONB хранение payload;

*   SQL индексация;

*   корреляция событий;

*   группировка инцидентов.


---


## Структура программы


### Router Layer

Маршрутизация HTTP запросов.


### Service Layer

Бизнес-логика приложения.


### Repository Layer

Работа с PostgreSQL.


### Analysis Microservice

Микросервис анализа угроз:


*   threat scoring;

*   correlation engine;

*   incident aggregation;

*   narrative generation.


### Database

Хранение:


*   событий;

*   источников;

*   аналитики;

*   инцидентов.


---


## Связи программы с другими программами

Backend взаимодействует:


*   с frontend-приложением;

*   PostgreSQL;

*   сервисом анализа угроз.

# 5\. Вызов и загрузка

Запуск осуществляется командой:


    make dev


или:


    go run ./cmd/api


Входной точкой программы является:


    cmd/api/main.go


---


# 6\. Входные данные

Входными данными являются события безопасности.

Формат:<br>JSON.

Пример:


    {
      "source_ulid": "01HX...",
      "type_ulid": "01HX...",
      "severity": 9,
      "title": "SSH brute force detected"
    }


---


# 7\. Выходные данные

Выходными данными являются:


*   JSON API ответы;

*   аналитические данные;

*   сведения об инцидентах;

*   агрегированные результаты анализа.


Пример:


    {
      "incident_id": "01HX...",
      "threat_level": "HIGH",
      "threat_score": 9.2
    }
